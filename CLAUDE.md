# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Capybara Cloud is a self-hosted, "bring your own cloud" PaaS engine. It is an Nx monorepo (global `nx` CLI; Nx itself is pinned in the root `package.json`, installed with `pnpm install` at the root) with a Go backend, a React frontend and a shared Go module. `README.md` has setup details, env vars and module status.

## Commands

Backend (run from `apps/backend`; config is read from `apps/backend/.env`):

```sh
supabase start && supabase db reset   # local Postgres + apply supabase/migrations
sqlc generate                         # REQUIRED before building: writes packages/shared-go/database (gitignored)
./run.sh dev                          # make dev -> bin/backend, runs with ENV=development
go test ./...                         # all backend tests
go test ./tests -run TestAuthSignupIntegration        # one test
go test ./internal/deployment -run TestX/subtest_name # one subtest
```

Shared module: `cd packages/shared-go && go test ./...`. `docker/service_e2e_test.go` has no build tag, so it needs a running Docker daemon. Use `-run` to skip it.

Every project has Nx targets, runnable from the root: `nx dev backend`, `nx test backend`, `nx sqlc backend` (sqlc generate), `nx dev frontend`, `nx run-many -t dev -p backend frontend`. Never use `./nx`.

Frontend (`apps/frontend`, pnpm workspace package, install from the root): `pnpm dev` (port 5173, proxies `/api` to `localhost:8888` or `API_URL`), `pnpm test` (vitest), `pnpm typecheck`, `pnpm build`.

API smoke requests: Bruno collection in `apps/backend/bruno`.

## Architecture

- **Two Go modules.** `apps/backend` depends on `packages/shared-go` through a `replace` directive in `go.mod`. It is not a `go.work` workspace, so run Go commands inside each module directory.
- **Database layer.** Migrations live in `apps/backend/supabase/migrations` and double as the sqlc schema. Queries live in `apps/backend/sql/queries`. sqlc writes code to `packages/shared-go/database`, which both modules import. `apps/backend/internal/database` and `apps/backend/temp/` are stale copies, so don't edit them. `sqlc.yaml` overrides some NOT NULL columns to nullable `pgtype`s because they are LEFT JOINed through `sqlc.embed`. Keep that in mind when you add columns to joined tables.
- **Backend layering.** `api/routes` mounts chi routers under `/api/*`. Handlers are in `api/handlers`, and `api/middleware` holds JWT auth (`login_guard`, `sid` cookie) and request logging. Business logic sits in `internal/<domain>` as one Go package per domain, each exposing a `Service` interface (some also have a `Repository` over sqlc `Queries`). DTOs are in `pkg/dto`. `main.go` manually wires every dependency, with no DI framework.
- **Deployment pipeline.** It runs asynchronously over channels. `deployment.Service` pushes a `DeployRequest` on `deploy_in_chan`. `deployment.Listener` (started as a goroutine in `main.go`) runs the steps extract → build → push → start and reports each `DeployStepResult`. The start step hands off to `masbro-worker`, which runs the image as a Docker container. The Docker client, port allocator and shared deploy types are in `packages/shared-go/{docker,deployment}`. The Dockerfile template is in `internal/deployment/templates`.
- **Frontend.** All backend calls go through `src/api` (`createApi()`), which owns URLs, cookies and the response envelope, and throws `ApiError`. Routes under `src/routes/_authed/` require a session. `routeTree.gen.ts` is generated by the TanStack router plugin.

## Testing conventions

- Dependencies are faked with hand-written stubs (`stubs.go`, `*_stubs.go` in each package): structs with configurable `*_return`/`*_err` fields and call counters. There is no mocking library, so add to the existing stubs instead of adding one.
- `apps/backend/tests/*_integration_test.go` builds the real router over stub services and drives it through `httptest`. These tests need no database. See `.claude/rules/testing.md`.
- Code style is snake_case for Go locals and params, matching the existing code.
